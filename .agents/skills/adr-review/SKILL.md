# ADR レビュー手順

設計に関する議論の結論を `docs/adr/` の ADR として作成または更新した際は、Claude にレビューを依頼してセカンドオピニオンを取得します。第三者の視点から設計の前提や見落としを点検することが目的です。

## ステップ 1 レビューの実行手段の選択と起動

状況に応じて、次の 3 つの手段のいずれかを選択してレビューを実行します。

* ローカルの `claude` コマンド
* サブエージェントの起動
* `swarm` ワーカーの起動

ローカルの `claude` コマンドを使う場合は、認証済みの `/Users/chikoski/.local/bin/claude` を利用します。サンドボックス外のバイナリとネットワーク通信を使用するため、`run_command` で `BypassSandbox: true` を指定して実行してください。`-p` と `--permission-mode plan` などを指定して非対話かつ読み取り専用で実行し、プロンプトに検査対象と観点を渡します。

サブエージェントを使う場合は、`invoke_subagent` ツールで `research` などの読み取り専用サブエージェントを起動し、プロンプトに検査対象と観点を渡します。

`swarm` ワーカーを使う場合は、`swarm` ツールの `add` アクションを呼び出して起動します。`name` には `adr-reviewer`、`model` には `claude-opus-5-5-high`、`workspace` には `inherit` を指定します。`claude-opus-5-5-high` のクォータが枯渇している場合は、`claude-sonnet-5-5-high` にフォールバックします。実行中にクォータ上限へ達した場合も、同じ代替モデルへ切り替えます。

## ステップ 2 レビュー依頼と検査観点

レビュー担当者への依頼内容には、レビュー対象の ADR ファイルパス、関連する既存の ADR、および [CLAUDE.md](../../../CLAUDE.md) と [AGENTS.md](../../../AGENTS.md) に記載された不変条件や設計原則を確認する指示を明記します。あわせて、レビュー担当者自身はファイルを直接編集せず、検査結果のみを出力または `@coordinator` 宛てにボードへ投稿するよう指示します。

レビュー担当者には次の 5 つの観点で ADR を検査させます。

* 背景と制約の正確性
* 検討した選択肢の網羅性
* 既存不変条件との整合性
* 境界条件と異常系の考慮漏れ
* 採用案のトレードオフと波及影響

背景と制約については、対象コードや関連 Issue の事実と食い違いがないかを確認させます。検討した選択肢については、見落とされている有力な代替案がないかを確認させます。不変条件との整合性については、`GlitchEngine` のセッション直列化、3 段フレームパイプラインのバッファと `Surface` 同期、`CpuSelfieSegmenterGraph` のパッケージ配置、および `Mp4VideoRecorder` と `MediaStoreHelper` の資源解放規約に違反しないかを点検させます。境界条件とトレードオフについては、エッジケースの扱いや既存機能およびテストへの波及影響が漏れなく書かれているかを確認させます。

## ステップ 3 レビュー結果の反映とエスカレーション

選択した実行手段の出力、サブエージェントからの返答、または `swarm_wait` と `read_board` を用いてレビュー報告を受け取ります。指摘事項は内容の性質に応じて自律対応とユーザーへのエスカレーションに切り分けます。

境界条件の補完、不変条件の明記、表現の明確化といった決定の大枠を変えない指摘は、メインエージェントが自律的に ADR へ反映します。修正した ADR の再確認が必要な場合は、同じ手段で再検査を依頼します。`swarm` ワーカーの場合は `post_message` で `@adr-reviewer` に依頼します。サブエージェントの場合は `send_message` で、ローカルコマンドの場合は修正内容を添えた再実行で依頼します。再確認のやり取りは最大 2 往復までとします。

一方で、採用した選択肢そのものへの異議、アプリ構成や保存仕様の変更提案、合意済みのトレードオフを覆す指摘があった場合は、自律的に決定を変更してはなりません。論点と各選択肢の利点および欠点を整理し、ユーザーへエスカレーションして判断を仰ぎます。

## ステップ 4 後処理

レビュー結果の反映またはユーザーへのエスカレーションが完了し、追加の確認が不要になったら後処理を行います。`swarm` ワーカーを起動した場合は、`swarm` ツールの `kill` アクションで `adr-reviewer` を終了します。ローカルの `claude` コマンドやサブエージェントを使用した場合は、完了を確認して次の作業へ進みます。
